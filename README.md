## 1. Project Overview

Dynamic memory allocation is a core responsibility of computer operating systems. When processes are loaded and terminated, memory becomes fragmented into isolated free holes — even when total free memory is sufficient to satisfy a new request.

This project implements an **academic dynamic memory allocation simulator in C**, modelling physical RAM partitions using a **Doubly Linked List** with dynamic block splitting and O(1) free-hole coalescing. An **AI extension in Python** uses a trained Random Forest classifier to analyse the workload and automatically recommend the best allocation strategy.

### Core Features

1. **Three Allocation Algorithms** — First Fit, Best Fit, Worst Fit implemented in C using a Doubly Linked List
2. **Dynamic Block Splitting** — splits a partition and inserts a new free-hole node in O(1) time
3. **O(1) Free-Hole Coalescing** — merges adjacent free blocks using `prev`/`next` pointers without scanning
4. **Side-by-Side Comparison** — runs all 3 strategies on the same workload and compares results
5. **AI Strategy Recommender** — analyses memory pressure, process size variance, and block distribution to recommend the optimal strategy

## 4. Data Structure: Why Doubly Linked List?

```
[ Block 1: Free (100 KB) ] <== prev / next ==> [ Block 2: P1 (200 KB) ] <== prev / next ==> [ Block 3: Free (150 KB) ]
```

1. **Physical Contiguity Modelling**: Physical memory blocks are adjacent. Each block has a left neighbor (`prev`) and right neighbor (`next`), exactly matching the DLL structure.
2. **O(1) Free-Hole Coalescing**: When process P1 in Block 2 terminates:
   - Checks `block->next`: if free → merge right in O(1)
   - Checks `block->prev`: if free → merge left in O(1)
   - Total coalescing time: **O(1) constant**
3. **Flaw of Singly Linked Lists**: Only has `next` pointer. Merging with the left neighbor requires an O(n) traversal from the head to find the predecessor.
4. **Flaw of Static Arrays**: Fixed capacity. Splitting or merging blocks requires shifting all subsequent elements — O(n) overhead.

## 5. Allocation Algorithms

| Algorithm | Strategy | Best Case | Worst Case | When it wins |
| :--- | :--- | :---: | :---: | :--- |
| **First Fit** | First block that fits | O(1) | O(n) | Balanced general workloads |
| **Best Fit** | Smallest block that fits (min fragment) | O(n) | O(n) | High memory pressure, tight partitions |
| **Worst Fit** | Largest block available (max fragment) | O(n) | O(n) | Large blocks, highly varied process sizes |

## 6. AI Strategy Recommender

The AI module learns from 5,000 synthetic workloads which algorithm performs best and why. It extracts 13 features from any new workload:

| Feature | Description |
| :--- | :--- |
| `num_blocks` | Number of memory partitions |
| `total_memory` | Total available memory (KB) |
| `num_processes` | Number of incoming processes |
| `total_requested` | Total memory requested (KB) |
| `mean_process_size` | Average process size (KB) |
| `std_process_size` | Standard deviation of process sizes |
| `memory_pressure` | `total_requested / total_memory` |
| `max_block_size` | Largest block size (KB) |
| `max_process_size` | Largest process size (KB) |
| `min_process_size` | Smallest process size (KB) |
| `std_block_size` | Standard deviation of block sizes |
| `mean_block_size` | Average block size (KB) |
| `max_size_ratio` | `max_process_size / max_block_size` |

A **Random Forest classifier** (180 trees, max depth 14) is trained on these features. The model learns: high pressure → Best Fit; large varied blocks → Worst Fit; balanced → First Fit.

## 7. Time & Space Complexity

| Operation | First Fit | Best Fit | Worst Fit |
| :--- | :---: | :---: | :---: |

| Free-Hole Coalescing | O(1) | O(1) | O(1) |

*where n = number of active memory blocks in the Doubly Linked List*

## 9. Common Viva Questions & Answers

**Q1: Why is Doubly Linked List better than an Array for dynamic memory?**  
In an array, splitting a block or merging adjacent free blocks requires shifting array elements — O(n). In a Doubly Linked List, splitting and merging with both neighbors takes O(1) time using pointer updates.

**Q2: What is external fragmentation?**  
External fragmentation occurs when total free memory is sufficient for a process but no single contiguous hole is large enough. The free memory is scattered in small isolated holes across the list.

**Q3: What is the main drawback of Best Fit?**  
Best Fit creates tiny leftover holes that are too small for any future process, increasing external fragmentation over time despite minimising waste per individual allocation.

**Q4: Why does Worst Fit sometimes perform better than Best Fit?**  
Worst Fit always picks the largest block, so the leftover hole is still relatively large and can accommodate future requests. Best Fit leaves behind many unusable tiny holes.

**Q5: How does the AI recommender choose a strategy?**  
It evaluates memory pressure (requested / total memory) and process size variance. High pressure → Best Fit (pack tightly); large blocks with high variance → Worst Fit (preserve large holes); balanced workload → First Fit (fastest).

**Q6: Why is `memory_ai_model.pkl` not uploaded to GitHub?**  
The model is regeneratable by running `train_ai.py`. Uploading binary `.pkl` files is unnecessary, adds repo size, and poses a security risk since pickle files can execute arbitrary code when loaded.

**Q7: What is the scoring formula used to label training data?**  
`score = allocations × 1000 − free_memory`. The 1000x multiplier makes allocation count the dominant factor. Remaining free memory acts as a tie-breaker when two algorithms allocate equally.
