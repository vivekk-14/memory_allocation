##  About the Project

When an OS loads processes into RAM, it must decide **which free memory block to assign** to each process. Bad decisions cause **memory fragmentation** — scattered free holes that together have enough space but no single hole is large enough.

This project:
- Simulates **First Fit**, **Best Fit**, and **Worst Fit** allocation strategies in **C** using a **Doubly Linked List**
- Lets you run all three on the same workload and compare results side by side
- Uses a **Python AI module** (Random Forest) trained on 5,000 workloads to **automatically recommend** the best strategy for any input

##  How It Works

```
┌─────────────────────────────────────────────────────┐
│               memory_simulator.c (C)                │
│                                                     │
│  Memory Blocks stored as a Doubly Linked List       │
│  [100KB] <-> [500KB] <-> [200KB] <-> [300KB] <-> [600KB]
│                                                     │
│  User selects: First Fit / Best Fit / Worst Fit     │

┌─────────────────────────────────────────────────────┐
│              ai_recommender.py (Python)             │
│                                                     │
│  Input: block sizes + process sizes                 │
│  ↓ Extract 13 features (pressure, variance, etc.)  │
│  ↓ Feed into trained Random Forest model            │
│  Output: recommended strategy + confidence %        │
└─────────────────────────────────────────────────────┘
```

##  Algorithm Comparison

| Algorithm | How it picks a block | Speed | Best used when |
|-----------|---------------------|-------|----------------|
| **First Fit** | First block that fits | Fastest | Balanced general workloads |
| **Best Fit** | Smallest block that fits (least waste) | Slower | High memory pressure, tight partitions |
| **Worst Fit** | Largest block available (most leftover) | Slower | Large blocks, highly varied process sizes |

---

## Complexity Analysis

| Operation | First Fit | Best Fit | Worst Fit |
|-----------|:---------:|:--------:|:---------:|
| Search — Best Case | O(1) | O(n) | O(n) |
| Search — Worst Case | O(n) | O(n) | O(n) |
| Search — Average | ~n/2 | all n | all n |
| Block Splitting | O(1) | O(1) | O(1) |
| Free-Hole Coalescing | O(1) | O(1) | O(1) |
| Auxiliary Space | O(1) | O(1) | O(1) |

*n = number of active memory blocks in the list*

##  Why Doubly Linked List?

Physical memory is a sequence of adjacent partitions. A Doubly Linked List maps this perfectly:

```
NULL <-- [Block 1: 100KB] <--> [Block 2: 500KB] <--> [Block 3: 200KB] --> NULL
```

| Feature | Why DLL wins |
|---------|-------------|
| **Block splitting** | Insert a new free-hole node with pointer updates only — O(1) |
| **Coalescing (merge)** | `prev` pointer gives instant access to left neighbor — O(1) |
| **vs Singly Linked List** | SLL needs O(n) scan to find the left neighbor for merging |
| **vs Static Array** | Array needs O(n) element shifting to split or merge blocks |

##  AI Model Details

### Training data
- **5,000 synthetic workloads** generated across 3 archetypes: tight partitions, large varied blocks, balanced general
- Each workload is labelled with the best-performing algorithm using the score: `allocations × 1000 − free_memory`

### Features (13 total)

| Feature | What it captures |
|---------|-----------------|
| `memory_pressure` | `total_requested / total_memory` — how tight is demand vs supply |
| `max_size_ratio` | `max_process / max_block` — can the biggest process even fit anywhere |
| `std_process_size` | Variance in process sizes — are requests uniform or wildly different |
| `mean_process_size` | Average request size |
| `std_block_size` | Variance in block sizes |
| `total_memory` | Total RAM available |
| `total_requested` | Total RAM needed |
| `num_blocks` | How many partitions exist |
| `num_processes` | How many processes to allocate |
| `max_block_size` | Largest single block |
| `max_process_size` | Largest single process |
| `min_process_size` | Smallest single process |
| `mean_block_size` | Average block size |

### Model
- **Random Forest** — 180 trees, max depth 14, stratified 80/20 train-test split
- Saved to `memory_ai_model.pkl` (auto-generated, not in repo)
